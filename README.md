# Tiltclimb

2D browser game: you climb vertically forever and you steer by tilting the phone.
It runs on Android Chrome (primary target) and on desktop with the keyboard.

Stack: [Excalibur 1.0](https://excaliburjs.com) · TypeScript · Vite 8. No backend.

## Commands

```bash
npm install
npm run dev        # dev server on http://127.0.0.1:5173
npm run build      # typecheck + build into dist/
npm run preview    # serve the build on http://127.0.0.1:4173
npm run typecheck
npm run lint       # Biome: lint + format + import order, without changing files
npm run lint:fix   # Biome: apply the fixes
npm run format     # formatting only
npm run check      # typecheck + lint + contrast + build: the gate before every commit
```

`npm run check:contrast` reads the colors from `src/ui/button.ts` and checks the WCAG ratio:
at least 7:1 for text on every background, 3:1 for borders. It is not an opinion about taste, it is a
number you can make fail.

Tooling that keeps entropy low: **Biome** (formatter and linter in a single binary, no
ESLint+Prettier to make them fight), TypeScript in `strict` with `noUncheckedIndexedAccess`,
`.editorconfig`, `.gitattributes` with LF. Biome does not touch `.agents/`, `.hermes/` and `openspec/`:
they are files generated by the OpenSpec CLI and reformatting them only creates noise in diffs.

### Text and buttons

Interface text and buttons are drawn with the canvas 2D API inside `ex.Canvas`
(`src/ui/ui-text.ts`, `src/ui/button.ts`), with the size measured before drawing and
`textAlign: center` for labels. It is not an aesthetic preference: Excalibur graphics are
drawn from the top-left corner and the actor anchor shifts the drawing by half a
size, while `ex.Text` measures itself lazily — combining them, a long text block ended up
several hundred pixels off screen. With the canvas the box and the ink
coincide by construction.

### Pre-commit hook

`.githooks/pre-commit` runs `tsc --noEmit` on the whole project and `biome check --staged`
on the staged files only (fast even as the repo grows). No extra dependency: a
`prepare` script in `package.json` enables the hook with `git config core.hooksPath .githooks` on every
`npm install`. Deliberate bypass, when needed: `git commit --no-verify`.

## Trying it on your phone

The sensors (accelerometer) only work in a **secure context**: `http://192.168.x.x:5173`
is not enough, HTTPS is required. The approach used here is a Cloudflare quick tunnel on the dev server:

```bash
npx vite                                   # or npm run dev
cloudflared tunnel --url http://127.0.0.1:5173
```

`vite.config.ts` is already configured to accept `*.trycloudflare.com` hosts and to do
HMR on `wss:443`, otherwise hot reload reconnects to the wrong port and dies.
The tunnel is temporary: the URL changes on every start.

## How to play

- **Menu**: on opening you see the detected tilt (value and bar). The first tap asks
  for the sensor permission.
- **Calibrate** sets the attitude you hold at that moment as zero and shows `Calibrated ✓`.
- **Sensitivity**: `−` / value / `+` row in the menu, five levels from 22° (soft) to 8°
  (twitchy), default **13°**. It is saved on the device and applies from the next run, without having to
  recalibrate: sensitivity is a scale factor, calibration is an offset.
- **Start game** starts from the zero of the last calibration; if you have not calibrated, the
  attitude with which you opened the menu counts.
- **In the run**: tilt left/right. From desktop ← → arrows or A/D; dragging
  also works on the phone if the permission is denied.
- **End of run**: you return to the menu with the score just made, the session's best score and
  the number of ships shot down.
- **CREDITS**: third button of the menu. It tells the hero's story (jump gone wrong,
  squad scattered, the climb as the only route), lists the assets with license and the author.
  `BACK` returns to the menu without touching the calibration.

## Levels

- **Endless levels of 1,500 px**: `level = floor(height / 1500) + 1`, triggered only by distance
  climbed. The level never goes down and never ends.
- **Each level is one step harder**, and inside a level difficulty is flat: climb speed +13 px/s per
  level from 190 up to 320 (level 11), a third ship alive from level 4 and a fourth from level 9, and
  the obstacle gap shrinking 5 px per level down to a floor of 210.
- **Ceilings**: past the levels that max out speed, gap and ships, difficulty stops growing; the
  counter does not.
- **Archetypes unlock on boundaries**: diver at level 3, hunter at 6, UFO at 9.
- **On screen**: `LV n` under the score at all times, and a `LEVEL n` banner for 1.2 s at each
  change. The score stays the bigger element.
- **The score does not read the level**: same formula, and the record is still the score.

## Difficulty

- **The climb accelerates**: from 190 px/s to 320 px/s, growing by `0.0135` px/s for every pixel
  scrolled. The cap is reached around 9,600 px, that is just under a minute of full climb.
- **Tied to height, not time**: “6,000 px” always means the same speed, so
  two runs over the same path have the same difficulty.
- **Everything scrolls together**: the starfield and the enemies use the current speed, not a
  constant. An enemy keeps its descent relative to the archetype even when the game
  accelerates.
- **Obstacles do not get closer**: they are placed at steps of 260 px of climb, so
  as the game accelerates they become farther apart in time, not closer in space. The game becomes
  faster, not more unfair.

## Feel and rendering

- **Rendered at device density**: the canvas backing store is computed so it matches the physical
  pixels of the painted area (capped at 2.5×), instead of a 720 px buffer stretched over a 1080 px
  screen. `antialiasing: false` plus `pixelArt: true` keeps the pixel-art edges hard.
- **Frame pacing follows the screen**: no fixed 60 Hz step, motion runs on the real elapsed time,
  so a 90 or 120 Hz phone draws that many distinct frames. Every speed is per second, so the
  movement is the same on any refresh rate.
- **Steering**: dead zone 1.5° as a **continuous ramp** (the response starts from zero at the
  threshold instead of jumping), smoothing tau 45 ms, full-scale horizontal speed 380 px/s — about
  1.9 s to cross the screen.
- **Background**: the near layer travels at 0.55× the climb speed, i.e. ~105 px/s at the start and
  ~176 px/s at the cap, so the world visibly moves.

## Records

- The best score and the best kill count are stored in the browser
  (`tiltclimb.bestScore`, `tiltclimb.bestKills`) and read back at startup, so they survive a reload,
  a closed tab and a phone reboot.
- The rule is simply "beat the best that exists": with nothing stored the bar is zero, so the first
  run of a fresh install is a record as soon as it scores.
- The menu separates the two ideas: `Last: 120   Best: 340   Kills: 5` after a run, and
  `Best: 340   Best kills: 12` when you open the game with a record and no run played yet.
- If the storage is denied or the stored value is garbage, the game keeps working with a best that
  lasts the session: `src/game/records.ts` validates every read and wraps every write.

## Pause

- **Round control in the top right** of the run, same size and style as the audio toggle in the menu.
  Tapping it freezes the run: no scrolling, no spawning, no score, no collision evaluation, and the
  fire button is disabled. The icon turns into a play triangle.
- **Resume by tapping anywhere** on the screen — the cover says `tap anywhere to resume`. The control
  is drawn only: the tap is resolved from the pointer position on the canvas, because Excalibur sends
  the same `pointerup` to several actors at once and its `screenPos` drifts with the camera.
- **Auto-pause when the page is hidden**, never auto-resume: a phone call or a tab switch does not
  cost the run, and coming back leaves you in control.
- A run always **starts unpaused**: the cover is hidden explicitly at creation, not left to a default.

## Invincibility power-up

- **Rare drop**: one enemy ship in ten leaves a spinning star where it died. It sits in the world and
  scrolls past, so the player collects it by moving into it; one at a time.
- **Eight seconds of invincibility**: asteroids and enemy projectiles do nothing, and **touching a ship
  destroys it** — same explosion, same points, same kill count.
- **A second pickup restarts the timer**, it never adds to what is left.
- **Look and sound**: the ship switches to an amber copy of the same hull (generated by
  `scripts/make-ship-variant.py`, since Excalibur 1.0.1 has no sprite tint), the last two seconds blink
  between the two colours, and a jingle plays on pickup.
- **Nothing else changes**: score, levels and the record never read the power-up, and the timer freezes
  while paused and resets at every run.

## Death

- **The world slows down**: on the fatal impact time drops to a quarter speed for 400 ms. The starfield
  and the ship's drift crawl, while the explosion plays at full speed so the blast is actually visible.
- **Nothing pays during the beat**: no spawns, no collisions, no score — the slowdown is a beat, not an
  extra life.
- **Time is always restored**: on the exit timer, on a scene change and when the page is hidden, so no
  run ever starts at a quarter speed.

## Firing

- **The whole bottom band fires**: a tap anywhere in the bottom 220 logical pixels produces one shot,
  exactly like the `FIRE` button, which stays as the visual cue.
- **Tap and drag are told apart on release**: under 12 px of travel and under 300 ms is a tap and
  fires; anything else is a steering drag, which never fires. Dragging inside the band does not
  steer either — that strip belongs to the controls.
- **One tap, one shot**: the band ignores taps that land on the button, so the button's own handler
  and the band cannot both fire.
- Coordinates come from the pointer page position against the canvas rectangle: Excalibur's
  `screenPos` drifts with the camera, which broke any fixed target deeper into a run.

## Cannon heat

- **Every shot heats the cannon**: 30 per shot against a maximum of 100, so four quick shots reach the
  limit. The cannon cools at 30 per second while it is not firing.
- **Overheating jams it**: at 100 the cannon refuses to fire — and taps add no heat, so hammering the
  button cannot delay the recovery. It fires again once the heat is back to 35, about 2.2 s.
- **The state is on screen**: a 140 × 12 bar 24 px above the fire button, cyan when cool, amber when
  hot, red when jammed, and the button reads `COOLING` and dims while jammed.
- **It cools on the game clock**: pausing freezes the heat, and every run starts cold. Score, levels
  and the record never read it.

## Combat

- **FIRE**: button at the bottom; one tap = one shot, no bursts (a 150 ms guard
  ignores the double event that some browsers generate from a single tap).
- **Enemy ships**: four types, each with its own sprite, movement and fire. They appear
  progressively, based on the height reached:

  | Type       | From     | Movement                            | Fire                   | Points |
  | ---------- | -------- | ----------------------------------- | ---------------------- | ------ |
  | Patrol     | at once  | oscillates while descending         | 1 shot                 | 25     |
  | Diver      | 2500 px  | descends fast diagonally            | burst of 2             | 35     |
  | Hunter     | 6000 px  | follows you horizontally (150 px/s) | fan of 3 at ±18°       | 45     |
  | UFO turret | 10000 px | stations at mid height              | burst of 4, long pause | 60     |

  The limit of simultaneous ships is 2, and it rises to 3 once the hunter is unlocked.
- **Immunity**: the hero's shots pass through asteroids and enemy ships pass through them
  in turn. Projectile and ship collisions are computed by hand
  (`src/game/combat-math.ts`), not by the engine: that is how the immunities stay explicit.
- **Score**: height (1 point every 20 px) plus the points of the type shot down: 25, 35, 45 or 60.
- Dying is instantaneous: an asteroid, a ship or an enemy projectile ends the run.

## Look

Spaceship with an animated trail, rotating asteroid field, parallax starfield
(256×256 recycled tiles + stars at two depths). The menu uses the same background at
reduced speed with the ship as an illustration.

The sprites replace the shapes drawn in code; **the hitboxes did not change
shape**: the ship uses a 56×34 collider (the sprite is 112×75, so bigger than the collider),
the asteroids a circle of radius 33 px on a 90-wide sprite, with an area comparable to the
old 120×28 bar.

## Loading screen

Excalibur's default loader (blue background, engine logo) is replaced by
`src/ui/loading-screen.ts`: starfield, two ships chasing each other with their trails, progress
bar and percentage tied to the real loading progress.

Two details worth knowing:

- The **ships are the real sprites** of the game (`playerShip2_blue`, `enemyRed1`): copied into
  `src/assets/ships/` and imported with `?inline`, so they end up in the bundle as data URLs and are
  available before any network asset arrives. Cost: ~7 KB of base64.
- Everything else is drawn with 2D primitives, and until the inline images are decoded
  (a few milliseconds) there is a chevron fallback: the screen cannot stay empty.
- It stays visible for at least 700 ms even with the assets cached (otherwise it would flicker) and the
  fade towards the menu is a black curtain in `menu-scene.ts`, not a loader effect: when
  loading ends the engine stops drawing the loader screen, so a
  fade there would fade towards the empty background, not towards the menu.

With `prefers-reduced-motion` ships and stars stand still. On a landscape screen the
"rotate the phone" notice already present in `index.html` applies.

## Audio

- **Music**: one track for the menu and one for the run, on loop, with the scene change.
- **Effects**: hero shot, a different shot for each of the four archetypes, a different explosion
  per type when a ship is shot down, a big explosion and an impact on the hero's death.
- **End of run**: defeat sound, replaced by a success sound if the score beats
  the session's best score (the first run does not count as best score).
- **Muting**: icon in the top right of the menu, state remembered on the device
  (`localStorage`, key `tiltclimb.muted`).
- **No audio before a gesture**: browsers block automatic playback, so the
  tracks start on the first tap or key. If audio stays blocked, the game runs silently.

The assets are regenerated from the CC0 sources with:

```bash
FFMPEG=/path/ffmpeg python3 scripts/prepare-audio.py      # effects + music (mono OGG)
python3 scripts/prepare-explosions.py                      # explosion frames (Pillow)
```

## Installable and offline

- **Manifest** (`public/manifest.webmanifest`) with the ship icons generated by
  `python3 scripts/make-icons.py`: installable from the browser, opens full screen, portrait.
- **Service worker generated at build time** by the plugin in `vite.config.ts`: it precaches every
  file in `dist` under a cache named after a fingerprint of the build, so a new deploy gets a new
  cache and the old one is deleted on activation. The worker itself is never served from the cache,
  or an old copy would keep reinstalling itself.
- **Documents are network-first**, assets cache-first; the registration asks for an update on every
  load, so the next open picks up a deploy. Nothing reloads the page, so a run is never interrupted.
- **Offline** works after the first visit: the loading screen, menu and a full run all come from the
  cache. With no worker support or a refused registration the game behaves like a plain web page.
